# xspeeria-architecture

Before implementation identify the authoritative requirement and current architecture.
Map business requirement → domain → component → data → API → UI → security boundary → observability.
Detect duplicate responsibilities, circular dependencies, hidden coupling, scalability risks, and architectural drift.
Never silently replace the documented stack. Record decisions and alternatives.
