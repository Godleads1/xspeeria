## Owner decisions

| # | Question | Answer | Effect |
|---|---|---|---|
| 1 | Staff second factor | "Email code, as in Figma" | 6-digit email code at every staff log-in; cannot be switched off (Figma's 2FA toggle removed). Dev prints codes to the server console; Resend in test mode until a domain exists. |
| 2 | Super Admin factor (Compliance Manual §14.2 requires a hardware key) | "Email code now, key later" | MVP: email code. **Release gate:** Super Admin must use a hardware security key before real customer money goes live. |
| 3 | Escrow Float on Revenue (8.5% return) | "the like the record not necessary the money stay with xspeeria" | Read as: a **record** of customer money waiting in escrow at partner banks (operations figure), **not** Xspeeria revenue, no return %. Earning on customer money stays out unless lawyers and partner banks approve (ADR-001). |
| 4 | Who approves refunds/reversals | "One staff with permission" + "Yes, that rule" | One approver with the Approve permission, **never on their own request** (SEC-008). System-started reversals need one approver. Every decision is audit-logged. |
| 5 | Cards and Adverts | "Hide both for MVP" | Cards tab, Adverts tab and Advert Placement setup not built. |
| 6 | Where disputes start | "App and staff" | Customers raise disputes in the app (this is Support, ADR-050); staff may open one for a customer. |

## Design corrections applied while building (no owner decision needed — existing rules)

- Account numbers: last 4 digits only (Figma reversal details show the full number).
- No "balance" wording ("Card Current Balance" — Cards hidden anyway).
- "Fee", not "spread": Xspeeria charges a fee; rates are set by users (ADR-005).
- Corridors: NG⇄GB and NG⇄US only (ADR-043); Figma's US⇄UK and other sample corridors are placeholders.
- Staff/User IDs are generated by the server (Figma's typed "User ID").
- Figma typos/mislabels fixed (Reject modal titled "Approve", Escalate button "Process refund", reset-password placeholders, email footer copied from another product).
- Role Setup list in Figma is a copy of the advert table; roles follow the Create Role screen: per module, Full Access / Read / Create / Update / Delete / Approve.
- Sample data (brands, currencies, e-commerce dispute text) replaced by real data.

## Build plan

- **A-1 (server):** staff accounts separate from customers; password + email code; httpOnly cookie session; configurable roles and permissions checked on the server for every admin call; append-only audit log; first Super Admin created by a command-line script.
- **A-2 (console):** login, email code, forgot/reset password, own profile, staff, roles, audit log.
- **A-3:** users, disputes/support, reversals (with the approval rule), fraud alerts, service outages, dashboard (escrow as a record; no Cards/Adverts).
